# Persona Alignment with LoRA Fine-tuning

This project demonstrates how to adapt a large language model (LLM) to adopt a specific personality or writing style using Low-Rank Adaptation (LoRA) and preference-based fine-tuning.

## Project Overview

The goal is to fine-tune a base instruction model to generate responses that reflect a specific persona—in this case, **Tony Stark (Iron Man)** with his sarcastic, witty, and concise communication style.

The project consists of two main stages:

1. **Data Generation** (`generate_training_data.ipynb`): Create preference pairs by generating responses in both a neutral and persona-specific style
2. **Model Fine-tuning** (`finetune_lora.ipynb`): Fine-tune the base model using LoRA to learn the target persona

## Project Pipeline

```
questions_raw.json (base questions)
        ↓
[Stage 1: Generate neutral responses]
        ↓
questions_response_pair.json
        ↓
[Stage 2: Generate persona responses]
        ↓
questions_preference.json (chosen vs rejected pairs)
        ↓
[Llama 3.2 1B + LoRA Fine-tuning]
        ↓
llama1b_lora.pth (adapted model weights)
```

## Files Description

### Input Data
- **`questions_raw.json`**: Base questions from a previous QA project (https://github.com/lealal/llm_router), used as the foundation for training data generation

### Generated Data
- **`questions_response_pair.json`**: Neutral responses generated by Llama 3.2 3B using Ollama in Stage 1
- **`questions_preference.json`**: Preference pairs containing:
  - `question`: The original question
  - `rejected`: Neutral response (generic/formal tone)
  - `chosen`: Persona response (sarcastic, witty Tony Stark style)

### Model Output
- **`llama1b_lora.pth`**: Fine-tuned LoRA weights (not the full model, just the trainable adapters)

### Utilities
- **`ollama_utils.py`**: Helper functions for local Ollama API calls and process management

## Usage

### Stage 1: Generate Training Data (`generate_training_data.ipynb`)

**Prerequisites**: Ollama running with llama3.2:3b available

This notebook:
1. Loads base questions from `questions_raw.json`
2. **Stage 1**: Generates neutral responses using base Llama model
3. **Stage 2**: Generates persona responses using a system prompt that defines the Tony Stark character
4. Creates preference pairs saved to `questions_preference.json`

**Note**: Data generation can take several hours depending on hardware (typically 10,000+ questions).

### Stage 2: Fine-tune with LoRA (`finetune_lora.ipynb`)

**Prerequisites**: HuggingFace token for Llama model access, Apple Silicon or GPU

This notebook:
1. Loads preference data and prepares train/val/test splits (85/5/10)
2. Initializes Llama 3.2 1B Instruct model
3. Applies LoRA layers to linear layers in attention and feed-forward modules
4. Trains for 5 epochs with advanced learning rate scheduling (warmup + cosine annealing)
5. Evaluates with multiple metrics:
   - **Loss**: Cross-entropy loss on test set
   - **Perplexity**: Exponent of loss (lower is better)
   - **BLEU Score**: n-gram overlap with reference (expected to be low—model learns generative diversity)
   - **Qualitative**: Before/after comparisons on sample prompts

## Results

### Model Adaptation

The fine-tuned model successfully adopts the Tony Stark persona:

| Aspect | Before Fine-tuning | After Fine-tuning |
|--------|-------------------|-------------------|
| Style | Formal, generic | Sarcastic, witty |
| Length | Long, detailed | Concise, direct |
| Tone | Neutral, helpful | Confident, clever |

**Example Output**: When asked "What is the best way to cook fried eggs?"
- **Before**: Generic cooking instructions with 4 methods and explanations
- **After**: "Come on, it's not rocket science... heat your pan with butter... that's the magic number. Now, if you'll excuse me, I have some actual engineering to attend to."

### Quantitative Metrics

- **Test Perplexity**: ~2.85 (model confident in generations)
- **Test BLEU**: 0.06 (indicates model generates novel expressions rather than copying training data—this is desirable)
- **Trainable Parameters**: 6.7M out of 1.2B (0.54% of base model)

### Key Findings

1. LoRA efficiently adapts the base model with minimal parameters
2. The persona is clearly visible despite low BLEU scores (which measure n-gram overlap, not style)
3. Overfitting is present but moderate (validation loss diverges from training after epoch 4)
4. The model maintains coherence and relevance while adopting the target style

## Technical Details

### LoRA Implementation

LoRA (Low-Rank Adaptation) works by:
- Freezing the original model weights
- Adding trainable low-rank decomposition matrices (A, B) to linear layers
- Only updating these matrices during training: `output = x·W + (x·A)·B`
- Using rank=8, alpha=16 (hardware-constrained choices for Apple Silicon)

### Training Strategy

- **Base Model**: Llama 3.2 1B Instruct
- **Fine-tuning Method**: Supervised Fine-tuning (SFT) on chosen responses
- **Optimizer**: AdamW with weight decay (0.1)
- **Learning Rate Schedule**:
  - Warmup: linear increase from 1e-5 to 2e-4 (20% of training)
  - Main: Cosine annealing from 2e-4 to 1e-6
- **Sequence Length**: 256 tokens (hardware constraint)
- **Batch Size**: 4 (Apple Silicon limitation)
- **Epochs**: 5

### Data Preprocessing

- Proper token masking: prompt tokens masked (-100) so loss only applies to responses
- Pre-tokenization before training to reduce per-batch overhead
- Custom collator handles variable-length sequences with padding

## Next Steps: DPO Fine-tuning

#### Current work in progress

The current implementation uses **Supervised Fine-tuning (SFT)** with only the "chosen" responses. Building on this foundation, the next phase will implement:

- **Direct Preference Optimization (DPO)**: A more efficient alternative to RLHF that directly optimizes for preference pairs
- Compare SFT vs DPO results on the same preference data
- Evaluate how DPO affects style transfer and reduces overfitting

## Hardware Notes

This project was developed on **Apple Silicon (M3 Pro)** with the following constraints:
- Uses FP16 precision to fit in memory
- Batch size limited to 4
- Sequence length limited to 256
- LoRA rank limited to 8

Adjustments for other hardware (NVIDIA GPU, TPU):
- Can increase batch size and sequence length
- Can use FP32 or mixed precision
- Can use larger LoRA rank for better expressiveness
